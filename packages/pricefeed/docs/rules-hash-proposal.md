# Q04 — existing contract and proposed rules manifest

Status: proposal for review, 03 October 2026. No canonical production hash is
selected or generated by this document.

Candidate library mechanics are now implemented in `src/rules.ts`. Encoding
starts with keccak256(UTF8("EROS_POLYMARKET_INDEX_RULES_V1")), then the fixed
schema fields in RULES_FIELDS, each using its declared ABI type. Text fields
venue, outcomeLabel and pricingPolicy are Keccak hashes of their exact UTF-8
bytes; no Unicode or case normalization is silently applied. Explicit bytes32
inputs encode their bytes; integer inputs must be canonical decimal strings.
The externalRulesDigest field holds a SHA-256 metadata evidence digest, while
the full manifest digest uses Keccak-256. Its inclusion does not approve the
external event mapping. Current development builder requires explicitly
unapproved diagnostic quote/quantity/failure policy hashes. No deployment or
canonical-owner acceptance is implied by these candidate bytes.

**Responsibility clarification.** The risk-side consumer contract is implemented:
it receives and pins a bytes32 indexRulesHash, includes sourceRulesHash in the
signed observation digest, and rejects mismatches. There is no missing risk
hashing function required for pricefeed development. The remaining Q04 work is
the shared listing/pricefeed dossier that determines that supplied bytes32; it
must not be described as unfinished risk ingress or a reason to wait to build
package-only manifest mechanics.

## What the project already specifies

- The implementation-plan PDF, section “Hash and change policy [Q04]”, requires
  an agreed canonical source-rules document and hashing format before
  initialization. It should bind venue, exact outcome mapping, time policy,
  units, impact method, rounding and failure semantics. It assigns the relation
  between sourceHash, rulesHash and indexRulesHash to factory/risk owners.
- `docs/requests/CP-PRICE-to-risk.md`, Q04, explicitly asks for that missing
  document, format and distinction; its presence is not evidence of a decision.
- `IMarketConfig.Listing` has separate sourceHash, rulesHash and indexRulesHash
  fields. No canonical document schema or derivation for those fields was found
  in the checked project docs or implementation.
- `RiskContextPort._initMarket` configures the index source with indexRulesHash.
  `PriceIngress._ingest` rejects a packet whose sourceRulesHash differs from the
  configured source state's rulesHash. Thus the required index-path equality is
  packet.sourceRulesHash = listing.indexRulesHash = sourceState.rulesHash.
  The last name is an ingress storage field, not proof of equality with
  Listing.rulesHash.
- The engine computes listingHash as keccak256(abi.encode(listing)), and risk
  profileHash similarly uses ABI encoding. Those are existing project precedents,
  not specifications for a pricefeed manifest.
- Risk tests use placeholder keccak256 hashes of strings. The local pricefeed
  demo hashes its LOCAL_DEMO_ONLY JSON manifest. Neither establishes the
  canonical production encoding.

## Proposal

Prepare a versioned index rules manifest inside this package, with a documented
fixed field order and Solidity ABI types. Use
`keccak256(abi.encode(versionDomain, ...approvedFields))`, following the project's
typed listing/profile hash convention. Do not use abi.encodePacked or hash an
arbitrarily formatted JSON file. The field/type schema and version domain remain
proposed until agreed with the Q04 owners.

The manifest should bind the venue, exact event/market/condition/outcome-token
mapping and approved Eros event-rules identity; reviewed external rules evidence;
quote/quantity policies; VWAP, rounding, fee and depth policies; N and maximum
spread; timestamp policy; and invalid/closure semantics. Policy references must
identify immutable definitions, not mutable labels. Q05-Q08/Q10 inputs remain
unresolved and must not be populated with invented production values.

Keep Listing.sourceHash and Listing.rulesHash independently supplied from the
approved listing dossier until their definitions are confirmed. The bot must not
derive or overwrite them under an assumed equivalence. The manifest's approved
digest would populate packet.sourceRulesHash and must match the listing's
indexRulesHash and configured source state at startup.

Retain exact encoded bytes, manifest version and the human-readable dossier for
review and reproducibility. Independently derived vectors should demonstrate
the same encoding/hash across implementations; mapping or economic policy
changes must change the digest, and presentation-only formatting must not.

The plan states that immutable source/signer/rule/N pins cannot change through a
bot config edit. A change uses the owners' approved new-listing/version process;
the worker quarantines an unexpected mismatch. No risk, CLOB, oracle or factory
implementation change is proposed here.

## What remains to close Q04

Factory/risk agreement on the exact manifest field/type schema, the identities
represented by sourceHash and Listing.rulesHash, and the canonical approved
indexRulesHash dossier. Subsequent event, units, failure-policy and calibration
decisions provide the concrete production values. This proposal can guide
package-only implementation without claiming those external decisions exist.
